## local-llm-chat v0.2.0

This release adds batch PDF processing and tightens the command-line
documentation around interactive chat and one-shot PDF workflows.

### Highlights

- Added batch PDF processing with `--batch-pdf-dir`.
  - Processes every top-level PDF in the input directory.
  - Defaults to `inputs/` when `--batch-pdf-dir` is provided without a value.
  - Writes one Markdown output per PDF.
  - Defaults output files to `outputs/<pdf-name>.md`.
  - Continues after per-file failures and exits with status `1` if any file
    failed.
- Added `--batch-output-dir` to choose the Markdown output directory.
- Batch PDF processing can be combined with `--pdf-images` for multimodal
  PDF analysis.
- PDF one-shot output no longer prints the interactive `LLM>` label.
- README usage sections now separate startup, interactive chat, one-shot PDF
  reading, and batch PDF processing.
- Added `inputs/` and `outputs/` to `.gitignore`.

### Compatibility Notes

- Existing interactive chat behavior is unchanged.
- Existing single-PDF commands continue to work.
- Existing output files in the batch output directory are overwritten when
  their names match generated Markdown paths.
- Batch processing handles top-level PDFs only; it does not recurse into
  nested directories.

### Examples

Process all PDFs in `inputs/` and write Markdown files under `outputs/`:

```sh
scripts/run.sh --batch-pdf-dir --instructions summarize.md
```

Process a specific input directory:

```sh
scripts/run.sh --batch-pdf-dir input-pdfs --batch-output-dir outputs \
  --instructions summarize.md
```

Use multimodal PDF page images during batch processing:

```sh
scripts/run.sh --batch-pdf-dir input-pdfs --batch-output-dir outputs \
  --pdf-images --instructions summarize.md
```
